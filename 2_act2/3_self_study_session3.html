16  Self-Study Session 3

In Chapter 13 to Chapter 15, every sample was a single row of tabular measurements. However, in industrial settings equipment is often monitored with several kinds of sensors at once, and each kind of sensor produces a different modality of data.

A production line might generate time series data from sensors (temperature, vibration, pressure) alongside visual data from cameras inspecting products, or thermal imaging systems monitoring equipment health. Multimodal machine learning combines these different data types to make more informed predictions than would be possible using a single modality alone. For instance, a temperature sensor might report elevated readings while a camera image shows visible wear; taken together, the two signals are stronger evidence of impending failure than either one alone.

In this session, we monitor the health of a simulated machine with two sensors:

  • A vibration sensor that records a short time series (80 time steps) of the vibration amplitude.
  • A thermal camera that takes a \(32 \times 32\) pixel thermal image (in °C) of the machine.

Our task is to classify the health status of the machine as Normal (0), Warning (1), or Critical (2). We will first train one model per modality and then combine the modalities with three fusion strategies:

  1. Early fusion: Concatenate the raw inputs of all modalities and train a single model on the combined input.
  2. Late fusion: Train one model per modality and combine their predictions.
  3. Intermediate fusion: Learn a compact representation (a feature vector) per modality and train a joint classifier on the concatenated features.

In this session, we will solely work with convolutional neural networks (CNNs) built with PyTorch, since they are well suited for both time series and image data and make it easy to combine multiple modalities with the different fusion strategies.

16.1 The dataset

The dataset is simulated and consists of 500 samples. You can download it as a JSON file or load it with the function load_multimodal_data below.

The thermal image shows a rectangular machine housing of random size, position, and orientation against a background at room temperature. The housing is slightly warmer than the room. Inside, the parts of the machine are visible as hot spots: the motor (large, left), the gearbox (center), the bearing (small, right), and the controller (top). The air inlet of the cooler (bottom) is a cold spot. Note that the size, the position, and the orientation of the housing vary slightly from image to image (it is rotated by up to 15° in either direction), so the parts are never at exactly the same pixel positions. The motor, the gearbox, and the bearing all get warmer with the current load of the machine, which varies from sample to sample. A thermal problem means that the gearbox and/or the bearing is warmer than the load (visible at the motor) would explain.

Behind the scenes, each sample has a hidden thermal level and a hidden vibration level (0 = fine, 1 = moderate, 2 = severe), and the overall health status is defined by their combination:

The vibration level affects the amplitude, the frequency, the noise, and the number of spikes of the vibration signal, but the ranges of neighboring levels overlap.

The hidden levels are part of the dataset, so that you can check what your models actually learn. Do not use them as model inputs: in practice, you would not know them.

import json
import urllib.request

import numpy as np

DATA_URL = "https://noxthot.github.io/ws26_industrial_datascience_manuscript/data/assets/act2/selfstudysessions/sss3_multimodal.json"


def load_multimodal_data(
    source: str = DATA_URL,
) -> tuple[np.ndarray, np.ndarray, np.ndarray, np.ndarray]:
    """Load the equipment monitoring dataset from a local file or a URL.

    Returns:
        ts_data: vibration time series (n_samples, 80)
        img_data: thermal images in °C (n_samples, 32, 32)
        labels: health status, 0 = Normal, 1 = Warning, 2 = Critical (n_samples,)
        levels: hidden levels (n_samples, 2), column 0 = thermal level, column 1 = vibration level
                0 = fine, 1 = moderate, 2 = severe
    """
    if source.startswith("http"):
        with urllib.request.urlopen(source) as f:
            data = json.load(f)
    else:
        with open(source) as f:
            data = json.load(f)

    return (
        np.array(data["time_series"]),
        np.array(data["images"]),
        np.array(data["labels"]),
        np.array(data["levels"]),
    )

NotePyTorch in a nutshell

In Chapter 9, we used a convolutional neural network (CNN) through sktime. In this session, we build the networks ourselves with PyTorch (torch), one of the most widely used deep learning libraries. Neural network models are well-suited for easy fusion of different modalities.

The Learn the Basics tutorial is a good starting point for understanding PyTorch fundamentals. Deep Learning with PyTorch: A 60 Minute Blitz is a brief introduction to building and training (convolutional) neural networks. For this session, you will need the following ingredients:

  • Tensors: torch.FloatTensor(array) turns a numpy array into a tensor. Convolutional layers expect images of the shape (batch, channels, height, width) and time series of the shape (batch, channels, length). The batch dimension counts the samples that the network processes at once, e.g., the 16 samples of a mini-batch or all 100 test samples. The channels dimension holds several values per pixel or time step: a color image has 3 channels (red, green, blue), a multivariate time series one channel per sensor. Our thermal images and vibration signals have a single channel each. A convolutional layer applies several filters, and each filter produces one output channel (a feature map): Conv1d(1, 16, ...) has 16 filters and thus turns 1 input channel into 16 output channels. More channels within the inner layers let the network detect more patterns in parallel: each filter learns its own pattern (e.g., a spike, an oscillation, or the edge of a hot spot), and the next layer combines these patterns into more complex ones.

  • Layers: nn.Conv2d, nn.Conv1d, nn.MaxPool2d, nn.MaxPool1d, nn.AvgPool1d, nn.Flatten, nn.Linear, nn.ReLU, and nn.Dropout from torch.nn. nn.Sequential(layer1, layer2, ...) chains layers into one module that applies them one after another.

  • A model: a subclass of nn.Module that creates its layers in __init__ and defines the data flow in forward. Calling model(x) runs forward.

  • Mini-batches: DataLoader(TensorDataset(inputs, targets), batch_size=16, shuffle=True) from torch.utils.data yields mini-batches taken from the full dataset. A TensorDataset can hold several input tensors per sample.

  • Training: the network outputs one raw score (called logit) per class. The training minimizes the cross-entropy loss between the logits and the true classes with the Adam optimizer, one mini-batch at a time. torch.softmax(logits, dim=1) turns logits into class probabilities.

The networks and data volume in this session are small enough to train on a CPU within seconds. Set torch.manual_seed at the top of your notebook for reproducibility.

16.2 Milestone 1: Two modalities, one health status

In Chapter 9, we used 1D convolutions through sktime to detect local patterns in time series. Now we build such a network ourselves. It consists of two parts: a feature extractor (features) that turns the time series into a compact feature vector of 32 values, and a classifier (classifier) that maps the feature vector to one logit per class. We use the full network in Milestones 1, 2, and 3; in Milestone 4, we reuse only its feature extractor.

NotePreparing the data for PyTorch

Splitting, standardizing, and reshaping the data is rather technical, so here is the code. Run it after loading the data and make sure you understand each step and the resulting shapes:

import torch
from sklearn.model_selection import train_test_split

# 1. Train-test split
# 80 % of the samples are used for training, 20 % for testing. All four arrays are
# split with the same random permutation, so that the time series, the image, the
# label, and the hidden levels of a sample stay together.
# stratify=labels keeps the class proportions (48 % Normal, 37 % Warning,
# 15 % Critical) equal in both sets. Without it, the 100 test samples could
# contain, e.g., only 8 or 22 critical samples just by chance.
(
    ts_train, ts_test,          # (400, 80) and (100, 80)
    img_train, img_test,        # (400, 32, 32) and (100, 32, 32)
    y_train, y_test,            # (400,) and (100,)
    levels_train, levels_test,  # (400, 2) and (100, 2)
) = train_test_split(
    ts_data, img_data, labels, levels, test_size=0.2, random_state=42, stratify=labels
)

# 2. Standardization
# Neural networks train best on inputs of the order of 1, but the images are in
# °C (roughly 10 to 70) and the vibration signals range from about -5 to 7.
# We subtract the mean and divide by the standard deviation. Both are computed
# on the training set only (one value per modality, over all samples and time
# steps or pixels) and then applied to both sets: the test set must not
# influence the training in any way, otherwise the test results are too optimistic.
# Using a single value per modality (instead of one per pixel) keeps the
# temperature differences between the parts of the machine intact.
ts_mean, ts_std = ts_train.mean(), ts_train.std()
img_mean, img_std = img_train.mean(), img_train.std()
ts_train_norm = (ts_train - ts_mean) / ts_std  # (400, 80), mean 0, std 1
ts_test_norm = (ts_test - ts_mean) / ts_std  # (100, 80), mean and std close to 0 and 1
img_train_norm = (img_train - img_mean) / img_std  # (400, 32, 32)
img_test_norm = (img_test - img_mean) / img_std  # (100, 32, 32)

# 3. Conversion to PyTorch tensors
# Convolutional layers expect a channel dimension right after the batch
# dimension: (batch, channels, length) for Conv1d and (batch, channels, height,
# width) for Conv2d. A color image would have 3 channels (red, green, blue), a
# multivariate time series one channel per sensor. Our data has a single
# channel, which unsqueeze(1) inserts as a new axis at position 1.
# FloatTensor converts to 32-bit floats, the default type of PyTorch layers.
ts_train_tensor = torch.FloatTensor(ts_train_norm).unsqueeze(1)  # (400, 1, 80)
ts_test_tensor = torch.FloatTensor(ts_test_norm).unsqueeze(1)  # (100, 1, 80)
img_train_tensor = torch.FloatTensor(img_train_norm).unsqueeze(1)  # (400, 1, 32, 32)
img_test_tensor = torch.FloatTensor(img_test_norm).unsqueeze(1)  # (100, 1, 32, 32)

# The cross-entropy loss expects the class labels as 64-bit integers (0, 1, 2).
# The test labels stay a numpy array, since we only need them for sklearn metrics.
y_train_tensor = torch.LongTensor(y_train)  # (400,)
NoteTraining, prediction, and evaluation

The following functions work for every network of this session, also for networks with several inputs. Copy them into your notebook after the data preparation:

import numpy as np
import pandas as pd
from torch import nn, optim
from torch.utils.data import DataLoader, TensorDataset


def train_model(model: nn.Module, loader: DataLoader, epochs: int) -> nn.Module:
    """Train a classifier with Adam and the cross-entropy loss.

    Each element of the loader is a mini-batch (*inputs, targets): one or more
    input tensors, followed by the class labels.
    """
    optimizer = optim.Adam(model.parameters())

    criterion = nn.CrossEntropyLoss()  # expects logits, not probabilities
    model.train()  # switches dropout on

    for _ in range(epochs):  # one epoch = one pass over the training set
        for *inputs, targets in loader:
            optimizer.zero_grad()  # reset the gradients of the previous batch
            loss = criterion(model(*inputs), targets)
            loss.backward()  # compute the gradients of the loss
            optimizer.step()  # update the weights

    model.eval()  # switches dropout off

    return model


def predict_proba(model: nn.Module, *inputs: torch.Tensor) -> np.ndarray:
    """Class probabilities (n_samples, 3) of a trained classifier."""
    with torch.no_grad():  # no gradients needed for predictions
        return torch.softmax(model(*inputs), dim=1).numpy()


def levels_vs_status(
    level: np.ndarray, pred: np.ndarray, level_name: str
) -> pd.DataFrame:
    """Cross tables of a hidden level against the true and the predicted status."""
    return pd.concat(
        [
            pd.crosstab(level, y_test, colnames=["status"]),
            pd.crosstab(level, pred, colnames=["status"]),
        ],
        axis=1,
        keys=["true health status", "predicted health status"],
    ).rename_axis(level_name)

16.4 Milestone 3: Early and late fusion

Early fusion feeds the raw inputs of both modalities into a single network. A CNN needs one common input format, so we bring the time series into the shape of the image: we zero-pad the 80 standardized values of the vibration sensor to \(32 \times 32 = 1024\) values, reshape them to \(32 \times 32\), and stack this “image” with the thermal image as a second channel. Note that this is just one way to make the time series compatible with a CNN (not necessarily the best one).

Late fusion needs no new network at all: it combines the predicted class probabilities of Milestones 1 and 2.

def as_image_channel(ts: np.ndarray) -> torch.Tensor:
    """Zero-pad time series (n_samples, 80) to 1024 values and reshape them to
    an image channel (n_samples, 1, 32, 32)."""
    padded = np.pad(ts, ((0, 0), (0, 32 * 32 - ts.shape[1])))  # (n_samples, 1024)
    return torch.FloatTensor(padded).reshape(-1, 1, 32, 32)

16.5 Milestone 4: Intermediate fusion

Intermediate fusion learns a feature vector per modality and classifies the concatenated features, all trained end-to-end in one network. The time series branch is the feature extractor of TimeSeriesCNN (32 features), the image branch is the feature extractor of ThermalCNN (64 features). The joint classifier concatenates both feature vectors (32 + 64 = 96 values) and applies Linear(96, 32) + ReLU + Dropout(0.3), followed by Linear(32, 3).
